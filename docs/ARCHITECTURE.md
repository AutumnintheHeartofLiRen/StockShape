# 桌面与 Agent 架构

当前 V1.4 是一个本地 Python 桌面应用。桌面负责展示与用户动作，耗时分析、行情更新和 AI 研究在独立进程中执行。AI 可连接云端接口或已启动的本机模型服务；行情与图表不依赖模型服务。

## 当前模块

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 桌面 | `desktop/main.py`、`chart.py`、`agent_panel.py` | 搜索、自选、图表、任务进度、对话与模型设置 |
| 本地服务 | `desktop/services.py` 的 `Store` | CSV 行情、自选、数据状态及私有策略调用 |
| 数据与分析任务 | `desktop/worker.py` | 独立进程执行更新/分析，以 JSON Lines 返回状态 |
| AI 任务 | `desktop/agent_worker.py` | 从 stdin 接收问题和内存上下文，返回研究进度与结果 |
| AI 配置 | `research_agent/config.py` | 校验服务配置，原子保存本机 `.env.local` |
| 模型接口 | `research_agent/provider.py` | 云端/本机 OpenAI 兼容 Chat Completions、认证、超时及有限重试 |
| 模型发现 | `research_agent/discovery.py` | 只读请求模型列表，供选择模型与检测连接使用，不进行推理 |
| Agent 循环 | `research_agent/runner.py` | 固定截止日，在轮数和工具上限内查询并组织回答 |
| 只读工具 | `research_agent/tools.py` | 白名单参数验证、有限行情和脱敏缓存结果 |
| 私有策略 | 本地 `private/strategy_engine.py`、`strategy_config.json` | 实际选股实现和参数，不进入公开发布目录 |

私有策略通过 `create_engine(store)` 提供 `verify_sources()` 与 `analyze_codes()`。AI 工具不调用这些方法，也不读取私有源码或参数配置；已有结果可读，但缺失时不隐式运行分析。

## 六个研究工具

| 工具 | 允许参数 | 输出与限制 |
| --- | --- | --- |
| `search_stocks` | `query`、`limit` | 本地代码/名称匹配，最多 20 条 |
| `get_market_status` | 无 | 数据日期、覆盖和失败数量；未来状态不能代替历史覆盖 |
| `get_watchlist` | 无 | 已保存自选及基础名称，最多返回前 200 只 |
| `get_bars` | `code`、`limit` | 最多 60 条 OHLCV、MA5/10/20/40 和区间摘要 |
| `get_analysis` | `code` | 任务交易日的已有脱敏判定，不提供私有指标和原始原因 |
| `get_candidates` | `limit` | 当前任务交易日的已保存候选，最多 30 只，标明缓存范围 |

股票代码须为六位数字字符串，未知参数、非法数量和未知工具均拒绝。工具不接受任意路径、代码或联网命令。它们只读 `Store` 的本地数据；更新时间、策略分析、自选增删继续由用户点击原桌面按钮执行。AI 研究与更新/分析任务互斥。

## 日期与来源

每轮启动时固定 `as_of`，默认使用本地有效行情日，无有效状态时使用上海当天日期。行情先截断至 `as_of`，再按截至该日的完整有效历史计算均线，最后裁剪返回数量。

分析缓存的 `summary.date` 必须等于 `as_of`。未来记录排除，旧缓存提示重新分析；股票自身行情过旧、历史不足、数据异常及同日缓存冲突均给出限制。最新缓存不能还原任意历史日。

所有工具使用同一返回信封：

| 字段 | 含义 |
| --- | --- |
| `status` | `ok`、`missing` 或 `error` |
| `data` | 白名单事实或缺失原因 |
| `as_of`、`data_date` | 任务截止日和实际使用行情日，无法确定时为空 |
| `strategy_version` | 当前为空；完整私有版本仍留在原分析缓存中 |
| `sources` | 相对运行数据路径、股票代码和记录日期，不含本机绝对路径 |
| `warnings` | 覆盖、日期、质量、版本及缓存范围限制 |

完整私有原因、指标、参数快照和源码指纹不进入提供给模型的工具输出。模型回答仍需要用户核对来源，不能把提示词约束当作事实正确性的保证。

## 配置、任务与失败

连接模式、本地运行器、模型地址、名称、密钥及调用上限来自 `.env.local`；非空 `AI_*` 进程环境变量优先。`AI_CONNECTION_MODE` 为 `auto`、`cloud` 或 `local`，默认 `auto` 兼容旧配置并按地址识别；`AI_LOCAL_RUNTIME` 为 `custom`、`ollama` 或 `lm_studio`。桌面提供云端与本地选择、地址预设、模型列表及连接检测，高级上限可编辑配置文件。

两种模式使用 `openai_compatible` 协议，要求 Chat Completions 和工具调用；HTTPS 用于远端服务，本地模式只连接回环地址并允许 HTTP 和空密钥。Ollama 默认 `http://127.0.0.1:11434/v1`，LM Studio 默认 `http://127.0.0.1:1234/v1`。应用不加载 GGUF 等权重，不管理模型下载、显存或运行器生命周期。

模型列表和连接检测仅请求基础地址下的 `GET /models`，不提交研究问题或推理请求。列表包含模型不意味着已经加载或支持工具调用，模型与运行器的模板和解析能力仍须实际验证。官方接口说明见 [Ollama](https://docs.ollama.com/api/openai-compatibility) 与 [LM Studio](https://lmstudio.ai/docs/developer/openai-compat/models)。

密钥以明文保存在本机配置文件，仅作为认证头发送给配置的服务端，不放入模型消息。设置中只有同一模式且同一服务地址下留空才保留旧密钥；更换地址或模式时不沿用，窗口内切回原模式可恢复原草稿。云端会收到问题、有限对话上下文和查询摘要；本地模式发往本机回环服务，应用不另行上传云端。本地服务可能按自身配置代理云模型，纯本机推理还须选择实际本地模型。两种模式都不会自动发送完整行情库、私有源码和参数文件。

研究进度、完成、未完成、失败和停止分别处理。单次问题、历史上下文、模型轮数、工具次数、响应大小和输出长度均有限制。模型请求可对暂时性错误重试一次；停止后不接纳迟到结果。对话只留窗口内存，不自动保存研究笔记。

SQLite 研究库、跨日快照、新闻与财报、持久记忆以及需要用户确认的写工具均属后续路线，见 [AI_ROADMAP.md](AI_ROADMAP.md)。公开导出与本地私有包的边界见 [PUBLISHING.md](PUBLISHING.md)；本地文件隔离不能阻止已获得私有包的人再次复制。
